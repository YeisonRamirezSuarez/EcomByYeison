# Velocidad — entrega A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the most expensive waits per request (Header, `/shop`, admin orders, repeated Clerk/settings calls) without touching security or i18n.

**Architecture:** The Header reads the session locally with `auth()` and loads locale, order count and settings in parallel; the admin shortcut moves to a client component. `getActor()` and `getSiteSettings()` are memoized per request with `React.cache`. `/shop` renders products on the server from URL filters. The admin orders API uses a projection that matches the UI.

**Tech Stack:** Next.js 16 App Router, React 19 `cache`, Clerk 7 (`auth`, `useUser`), Sanity client 7 (GROQ).

**Spec:** `docs/superpowers/specs/2026-10-06-speed-a-design.md`

## Global Constraints

- UI copy stays in Spanish/i18n exactly as today; no visual change except `/shop` filters in the URL and the admin button appearing after Clerk loads in the browser.
- Do not touch `proxy.ts` CSP/nonce, the locale cookie, or `"use cache"`/`cacheComponents` (entrega B).
- `/admin` access stays enforced on the server (layout + `requireSection`); the client `AdminLink` is a shortcut only.
- A demoted user must be rejected on their next request: `getActor()` keeps calling `currentUser()` (memoized per request only, never across requests).
- Pure modules tested by `scripts/check-permissions.mjs` may only use type imports (run with `node --experimental-strip-types`).
- Dev server only on port 3000 (stop whatever holds 3000/3001 first).
- No new dependencies.

## Review Focus

1. Odd `/shop` URLs — `?category=no-existe`, `?price=abc`, `?brand=a&brand=b`, empty values — render the empty state or ignore the bad filter, never crash. (Pinned by Task 3 `readShopFilters` asserts.)
2. Changing one `/shop` filter keeps the other two and any unrelated param; "limpiar filtros" removes only `category`, `brand`, `price`. (Pinned by Task 3 `shopHref` asserts.)
3. Logged-out visitor and logged-in `cliente`: no admin button, no hydration warning; staff see it after Clerk loads. (Task 2 browser step.)
4. `React.cache` on `getSiteSettings` keyed by the `draft` flag: the editor iframe still shows the draft for `configurar`, anonymous `/?vista-previa=1` still shows published. (Task 2 browser/curl step.)
5. Admin order whose product was deleted (`product->` is `null`) or with no `products`: list and drawer still render. (Task 4 step: drawer already guards with `?.`; verify by reading `OrderDrawer.tsx` and keeping the projection's `product->{...}` nullable.)

- [ ] **Step 3: Implement `lib/shopFilters.ts`**

```ts
export type ShopFilterKey = "category" | "brand" | "price";
export type ShopFilters = Record<ShopFilterKey, string | null>;

const KEYS: ShopFilterKey[] = ["category", "brand", "price"];

const first = (value: string | string[] | undefined) => (Array.isArray(value) ? value[0] : value) || null;

// Filters from the page's searchParams. Bad price values are handled later by parsePriceRange.
export function readShopFilters(params: Record<string, string | string[] | undefined>): ShopFilters {
  return { category: first(params.category), brand: first(params.brand), price: first(params.price) };
}

// The /shop URL after changing one filter ("all" clears the three), keeping any other param.
export function shopHref(current: string, key: ShopFilterKey | "all", value: string | null): string {
  const params = new URLSearchParams(current);
  for (const k of key === "all" ? KEYS : [key]) params.delete(k);
  if (key !== "all" && value) params.set(key, value);
  const query = params.toString();
  return query ? `/shop?${query}` : "/shop";
}
```
